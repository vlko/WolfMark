WolfMark shows times the way you want them, the macOS/Linux app gets the history menu, and the start is measured and a bit quicker.

## ✨ New

- **Date and time settings** – Settings → *General*
  - **24-hour time** (on by default): times read `13:45` whatever the language or the system region would use. Turn it off for `1:45 PM`.
  - **Dates and times in the app's language** (on by default): day and month names follow the language chosen in WolfMark; off, they follow the system's region settings. The Windows and the macOS/Linux app used to differ here.
  - Both apply after a restart, like the language.
- **History menu on macOS and Linux** – right-click a note in the history: **change tag**, **open folder**, **copy link** and **move to trash** (with a question first), as on Windows. Markdown files opened from elsewhere get **open folder** too.

## 🔄 Changed

- **Quicker start** – the editor gets the focus as soon as the last note is open; the week, history and calendar fill in right after, and the editor no longer prepares an empty document first. From launch to typing it now takes about 550 ms on the test laptop in the balanced power mode (about 50 ms less than 0.6.0); in the battery saver mode Windows slows every app down noticeably (1.2–1.6 s there). Measurements in [ADR 0011](../adr/0011-startup-time.md).
- **Calendar** – the week strip and the month view are the calendar; the year view from the original plan will not come ([ADR 0004](../adr/0004-flat-design.md)).

## 🐛 Fixed

- **A change made in another app could reload the open note twice** on Windows – Windows sometimes reports the same write again a moment later; it is now recognised.
- **"Sync now" for Claude Code waited 5 seconds** when real-time sync was on; it runs right away. Transcripts written during a sync no longer start another one immediately.
- **Slovak:** the week and calendar legend said "No tag" instead of "Bez tagu".
- The demo (`--demo`) could not start in a folder that did not exist yet, and its deleted notes went to the Windows Recycle Bin instead of staying in the demo folder.

## 🛠️ Under the hood

- **Smoke tests in CI** run the real published apps on demo data: on Windows the Native AOT build (no .NET or VC++ runtime needed on a clean PC, single instance, `.md` files as arguments, screenshots, startup time) and on Linux the Avalonia app under Xvfb. Locally: `tools/smoke-windows.ps1`, `tools/smoke-linux.sh`.
- Failed tests show up as annotations on the CI run; GitHub Actions moved to their Node 24 versions.
- New tests: autosave survives a killed process, the Claude Code sync schedule, the history actions.
