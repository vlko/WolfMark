WolfMark opens every Markdown file now – not only your notes – and the settings got some order.

## ✨ New

- **Open .md files with WolfMark** – on Windows, macOS and Linux (Settings → *General* → *Markdown files*; Windows asks you to confirm it in *Default apps*, on macOS Finder also lists WolfMark under *Open With*).
  - A note from your notes folder opens in the main window, on its day.
  - Any other file opens in **its own window**, like the full view: the folder and the file name on top, formatting, Raw/Formatted.
  - It is **not saved on its own** – *Save* (`Ctrl+S`, `⌘S`) lights up once you change something, and closing asks about unsaved changes. A change made by another program is reloaded, or, with your edits pending, you choose.
  - Saving keeps the file's encoding and line ends, so an unchanged file stays byte for byte the same. The status bar shows when the file was created and modified, its word count, encoding and line ends.
  - **Copy to my notes** in the corner of the editor makes the file a note of today.
  - Opened files appear in the **history** with the time you last opened or saved them, the file name in place of the tag and the full path on hover.
  - The same from the command line: `WolfMark.exe C:\path\file.md` hands the file to the running WolfMark.
- **Open link in browser** – links in notes stay non-clickable (a click places the caret), but a right click on a web link offers to open it. Only `http`, `https` and `mailto` links open.
- **Settings in categories** – *General*, *Appearance*, *Editor*, *Claude Code* and *Index & diagnostics* in a list on the left.

## 🎨 Polish

- The *Imported from Claude Code* badge sits closer to the corner of the editor.
- Tables read as their cells in the history and search previews ("Method · Path · Notes") instead of pipes and dashes. Existing notes get the new preview when they change, or all at once with *Rebuild index*.

## 🛠️ Under the hood

- .NET 11 RC3 – a security release of the runtime.
- One running WolfMark per data folder: a second start, also from another copy of the app, hands its file over and ends. A development build runs next to the installed one with `--demo`.
- New README telling why WolfMark exists, with fresh screenshots; `--screenshots` always generates the demo anew.
